# Frontend Standards

- Inspect the existing project before changing architecture.
- Prefer the smallest correct change.
- Do not refactor unrelated code.
- Reuse existing components, utilities, hooks, and patterns before creating new ones.
- Keep UI components focused on presentation and interaction.
- Keep business logic close to the feature that owns it.
- Avoid introducing dependencies unless there is a clear benefit.
- Preserve existing naming conventions.
- Use single quotes, semicolons, trailing commas, and 2-space indentation when consistent with the project.
- Prefer readable code over clever abstractions.
- Do not add comments for obvious code.
- When changing behavior, verify affected states and edge cases.
